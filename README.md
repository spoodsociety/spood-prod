# Spood Production

Static app for the shop floor: Bin View, Print Plan, Inventory, Customers. Served by GitHub Pages at https://spoodsociety.github.io/spood-prod/.

- `index.html` page and boot; `orders.js` Bin View, Order Desk, Customers; `printplan.js`; `inventory.js`; `collections.js` the collection editor (Inventory → Collections); `items.js` the item editor (Inventory → Items, an item's name, or Edit on a tile); `supabase.js` the only data layer.
- Data: Supabase project `hkllbpipcfzzppbgkzrh`, schema `hq`, reads and writes through RPC only (`read_orders`, `inventory_rows`, `resolve_lines`, `read_app_state`, `save_order`, `complete_order`, `undo_order_done`, `set_line_state`, `apply_moves`, `set_app_state`). Stock is never computed in the browser. Done orders carry `done_at`/`done_by`/`done_prev` (from `order_history`, app-marked only) for Bin View's Done list and its Undo.
- Sign-in: Supabase Auth (email + password). The database refuses every call without a session, and only emails in `hq.allowed_users` can create an account. The key in `supabase.js` is the publishable key; it is public by design and grants nothing on its own.
- Permissions: every `hq` function is signed-in only (`authenticated`, plus `service_role`); none is callable by PUBLIC or anon, and new functions start that way (default privileges, migration `hq_functions_signed_in_only`). Only the `waitlist-signup` edge function is public, by design: one fixed insert into `hq.waitlist`.
- Database changes: SQL files in `migrations/` (reviewed here, applied to the Supabase project by hand; the applied history lives in Supabase's migration table).
- Deploy: run `./stamp.sh` (bumps the module version in the import map so browsers don't keep stale modules), commit, push to `main`; Pages publishes the root.
- Order lines: `save_order` resolves any line with no item picked through `hq.resolve_line` (exact product/color/size match, learned aliases in `hq.line_aliases`), creates the variant when the catalog already offers that colorway, and otherwise leaves the line `unmatched` and visible (Bin View count, Order Desk flag). A person picking an item for a line is remembered as an alias — unless the line's words disagree with the pick.
- A line's `text` is what the order said; a pick never replaces it (the catalog name only when the line never had words). `save_order` checks every pick against the words (`hq.line_check`: size word, color names) and stores a disagreement on the line (`conflict`, e.g. "Text says Large"); Bin View, Print Plan and the Order Desk show it as the orange pill, a new one is logged (`pick_conflict`), and nothing blocks. The Order Desk gives a product made in several sizes no size until a person picks one.
- Print Plan → Bin View: lines whose pieces are on a printer show Printing/Printed in Bin View (`print_src: plan`). Stock pieces printing count for the open lines that need that item, soonest ship date first; when the batch is finalized those lines go back to automatic (shelf). The sync never reverts a line from a plan copy older than the orders. A person setting a line back to Needs printing (or Reset) takes its piece off any printing or in-review batch in the same save (`hq.plan_drop_pieces`, logged as `plan_piece_removed`), so the plan can't put it back to Printing. A piece already finalized to that order is released too: the batch stays in history and the piece's outcome there becomes failed (`reset: true`), so the line stays Needs printing and the batch offers Reprint (migration `reset_releases_finalized_piece`).

- One shelf count everywhere: every screen reads counts and shelf allocation from the same server answer (`inventory_rows` + `read_orders`, both from `hq.shelf_alloc`), and every save that can move a count or a shelf piece (line state, Done/Undo, a count or adjust, an order edit, a plan save) re-reads both, so Bin View, Print Plan and Inventory change together. Finalizing a batch puts its to-stock pieces on the shelf count in the same plan save (`hq.plan_stock_sync`, remembered per batch in `hq.plan_stock`; reopening or undoing takes them back off; logged as `plan_stock`). A shelf count is sent with the number the person was looking at (`expect`); if the shelf changed meanwhile, `apply_moves` hands it back as `changed` and the screen asks them to check and save again.

- Collections: Inventory → **Collections** builds or edits a collection: name, sold as accessory set and/or complete enclosure, and its pieces (pinned colorway, size, qty, complete-enclosure-only, choices such as Door/Floor with a default). `hq.save_collection` checks and saves the whole collection at once (stale-edit check, one default per choice, a complete enclosure must list the Enclosure piece, `app_log` kind `collection_saved` with before/after) and flags a pinned colorway the piece isn't listed in. Retire hides a collection from the Order Desk, the resolver and inventory labels; nothing is deleted.

- Backup: Inventory → **Backup** downloads every table in `hq` as one dated JSON file (`hq.backup_data`, signed-in users only, tables listed at run time so new ones are included; each download is logged as `backup_downloaded`). The functions and migrations are in this repo, so the file plus the repo is a full rebuild. A nightly automatic copy is still to do.

- Items: Inventory → **Items** (every piece), an item's name on the shelf, or **Edit** on a tile opens the item editor: name, other names it answers to (aliases), type, default color, customer-picks-color / tracked / add-ons bar, note; sizes (name, filament g, print minutes, profile, remove / bring back); colors offered; and every variation (inventory name, size, color, door/option, note, remove / bring back, learned order wording to forget). `hq.read_item` reads it, `hq.save_item` checks and saves all of it at once (stale-edit check, `app_log` kind `item_saved` with before/after). Renaming keeps the old name as an alias unless it is taken off, and inventory names follow a rename or a size/color change unless one was typed by hand; an old inventory name stays findable when its words still agree with the item. Changing a variation's size, color or option moves its sku with it, forgets the wording learned for it and re-checks the open orders it is on against their words (`line_check`, shown as the orange pill). A variation is removed only at 0 on the shelf and off open orders. Shelf counts are never touched.

- Print Plan → **Auto-plan**: queues the open pieces the way they have been run before. Every batch that reached a printer is the history (kept in the plan itself): which printers an item + size runs on and the most pieces that went on one plate. Auto-plan makes one queued batch per item + size + color, soonest ship date first, on the least busy of that item's usual printers (those with at least half the runs of its most-used one), split at the plate count. Left for a person: pieces never printed in that size, custom sizes, lines not in the catalog, shelf pieces and anything already picked by hand. It respects the "Ships by" filter, is one Undo, and queued batches don't change any line's status. No settings: assigning a piece by hand once teaches it.
- Print times: a piece's time is the one saved on its item's size (Inventory → Items; `inventory_rows.print_minutes`), else a rough guess from its name, shown with "~". The commit bar shows only once a printer is picked.
