# Spood Production

Static app for the shop floor: Bin View, Print Plan, Inventory, Customers. Served by GitHub Pages at https://spoodsociety.github.io/spood-prod/.

- `index.html` page and boot; `orders.js` Bin View, Order Desk, Customers; `printplan.js`; `inventory.js`; `collections.js` the collection editor (Inventory → Collections); `supabase.js` the only data layer.
- Data: Supabase project `hkllbpipcfzzppbgkzrh`, schema `hq`, reads and writes through RPC only (`read_orders`, `inventory_rows`, `resolve_lines`, `read_app_state`, `save_order`, `complete_order`, `undo_order_done`, `set_line_state`, `apply_moves`, `set_app_state`). Stock is never computed in the browser. Done orders carry `done_at`/`done_by`/`done_prev` (from `order_history`, app-marked only) for Bin View's Done list and its Undo.
- Sign-in: Supabase Auth (email + password). The database refuses every call without a session, and only emails in `hq.allowed_users` can create an account. The key in `supabase.js` is the publishable key; it is public by design and grants nothing on its own.
- Database changes: SQL files in `migrations/` (reviewed here, applied to the Supabase project by hand; the applied history lives in Supabase's migration table).
- Deploy: run `./stamp.sh` (bumps the module version in the import map so browsers don't keep stale modules), commit, push to `main`; Pages publishes the root.
- Order lines: `save_order` resolves any line with no item picked through `hq.resolve_line` (exact product/color/size match, learned aliases in `hq.line_aliases`), creates the variant when the catalog already offers that colorway, and otherwise leaves the line `unmatched` and visible (Bin View count, Order Desk flag). A person picking an item for a line is remembered as an alias — unless the line's words disagree with the pick.
- A line's `text` is what the order said; a pick never replaces it (the catalog name only when the line never had words). `save_order` checks every pick against the words (`hq.line_check`: size word, color names) and stores a disagreement on the line (`conflict`, e.g. "Text says Large"); Bin View, Print Plan and the Order Desk show it as the orange pill, a new one is logged (`pick_conflict`), and nothing blocks. The Order Desk gives a product made in several sizes no size until a person picks one.
- Print Plan → Bin View: lines whose pieces are on a printer show Printing/Printed in Bin View (`print_src: plan`). Stock pieces printing count for the open lines that need that item, soonest ship date first; when the batch is finalized those lines go back to automatic (shelf). The sync never reverts a line from a plan copy older than the orders.

- Collections: Inventory → **Collections** builds or edits a collection: name, sold as accessory set and/or complete enclosure, and its pieces (pinned colorway, size, qty, complete-enclosure-only, choices such as Door/Floor with a default). `hq.save_collection` checks and saves the whole collection at once (stale-edit check, one default per choice, a complete enclosure must list the Enclosure piece, `app_log` kind `collection_saved` with before/after) and flags a pinned colorway the piece isn't listed in. Retire hides a collection from the Order Desk, the resolver and inventory labels; nothing is deleted.
